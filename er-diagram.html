How the rows connect, in words

  1. An order header has many order items. An order item is one subscription line: start date, expire date, package, and subscription id.
  2. The package (pkg_def) says whether the term is measured in days, weeks, months, or years, and how many of those units.
  3. The NCA offering (news_offering) says whether that package is pay-as-you-go or a contract, and which instalment plan a contract uses.
  4. Cash lives on news_financial_transaction, one row per movement, stamped with a product code, a gross amount, a GST amount, and a payment sequence.
  5. Earned revenue is one row per order item, per product code, per earned date.
  6. The worklist (news_currently_earning) holds the order items still being earned. Fully earned ones are deleted.
  7. A contract points at the same order item and subscription, and has instalments. Each instalment has a due date and may point at a payment.
  8. When a contract's product code changes, the mapping table records the previous code for that package.
  9. The 4-character product code is what the weekly file groups by. A separate map, not in these tables, turns that code into the five-part JDE account.

Think standard Documented in the help file

orderhdr

The order. Primary key orderhdr_id. Also has order_date.

order_item

One subscription line on the order. Primary key orderhdr_id + order_item_seq.

  • start_date — start date of the subscription
  • expire_date — expire (stop) date of the subscription
  • pkg_def_id — which package
  • subscrip_id — which subscription
  • calendar_unit — 0 day, 1 week, 2 month, 3 year. The earned-revenue job reads this unit from pkg_def, not from the order item.
  • billing_type — 0 undefined, 1 balance due, 2 installment billing. The job does not use this. It uses news_offering.contract_offer instead.

subscrip

The subscription. The contract join requires order_item.subscrip_id to match news_customer_contract.subscrip_id. The help file describes subscrip_id as the subscription's sequential id.

pkg_def

Package definition. Primary key pkg_def_id.

  • calendar_unit — 0 day, 1 week, 2 month, 3 year
  • n_calendar_units — how many of those units
  • revenue_percentage_option — 0 manual percent, 1 relative percent. Present on the package. The earned-revenue procedures do not read it.

product

Standard Think product (product_id, name in column product). It has no 4-character accounting code. That code is an NCA column on the financial transaction.

installment_plan

A standard Think table in the Order Item submodel. The job does not read it. Contracts use the NCA table news_instalment_plan (spelled with an s).

NCA extension Seen only in the procedures

news_offering

  • pkg_def_id
  • contract_offer — empty means PAYG; filled means contract
  • status — the job keeps rows where this is Active
  • instalment_plan_id — contracts only

news_instalment_plan

  • instalment_plan_id
  • total_instalment_count

news_financial_transaction

The cash. Joined to the order item and the product code.

  • orderhdr_id, order_item_seq, pkg_def_id
  • product_accounting_code
  • product_gross_amount, product_gst_amount
  • payment_seq — ties a contract payment to an instalment
  • updated — must fall after the historical floor and on or before the earned date

news_earned_revenue

One amount per order item, product code, and earned date. The weekly file is these amounts, after the "subtract earlier dates" step, summed by product code.

  • orderhdr_id, order_item_seq
  • product_accounting_code
  • earned_date, earned_amount

news_currently_earning

Worklist of order items not yet fully earned. Same order-item and product-code identity. Deleted when earned catches up with net cash.

news_customer_contract

  • customer_contract_id
  • orderhdr_id, order_item_seq, subscrip_id

news_customer_contract_instalment

  • customer_contract_id, customer_contract_instalment_seq
  • payment_seq, due_date

news_earned_revenue_pac_mapping

Previous product code for a package, used when a contract's code changes.

  • pkg_def_id
  • product_accounting_code — the new code
  • prev_product_accounting_code

news_pkg_def_allocation and news_allocation_detail

Named in a comment only. Not read by the calculation. The comment describes pkg_def_id, effdt, allocation_id, and on the detail allocate_to plus allocation_pct. This is the closest thing in the script to a revenue-split percentage, and the job does not use it.

JDE Outside Think

jde_account_string

Not a table in the Think help, and not written by these procedures. The curator maps the 4-character product code onto this account.

  • Entity — legal entity
  • Publication — masthead, and print versus digital
  • Department — team
  • Object account
  • Subsidiary — with the object, the digital product or the print channel and day

Entity + Publication + Department is the business unit / cost centre.
