How the pieces fit

One package, followed from the split recipe to the weekly file JDE receives.

Home Algorithm Data model

The product code is the joint. A package is given a recipe that names two or more codes and a percent for each. Cash is stored on those codes. The weekly job never reads the percent. It earns whatever cash is already sitting on each code, and the file adds every subscriber’s movement into one integer per code.

The example is a real recipe, not a real subscriber. Package TA_TADS450G_W04, “The Australian Digital Pass & Weekend Paper Delivery”, uses allocation 2370 from 1 July 2025. The percents below are that recipe. No customer’s cash is shown.
  1. Think

    A subscriber buys a package

    pkg_def is the commercial product: the term, and whether time is counted in days, weeks, months, or years. The offering on that package says pay-as-you-go or contract. That flag chooses the weekly formula later. It does not choose the split.

    This one is TA_TADS450G_W04. The package prefix TA_ is The Australian. The product codes it pays will start with AU, not TA.

    Joined by the latest effective date on the package
  2. NCA

    The package carries one current recipe

    news_pkg_def_allocation points a package at an allocation id, dated with effdt. The extract keeps only the latest date. Many packages share one id. 10,283 packages have a recipe. 735 do not, including registration, staff access, trials, and free passes.

    This package’s current row is allocation 2370, status Active, effective 1 July 2025. The header is news_allocation. The lines are news_allocation_detail. They add to 100%.

    Navy is AUCD, 68.965517%. Green is AUCW, 31.034483%.

    Stored exactly as 68.965517% and 31.034483%. Of every 100 ex-GST, that is the share assigned to each code. The finance sheet’s Australian weekend column is 69% digital and 31% print. Close to this recipe, and not the number the recipe uses.

    Joined by the 4-character code
  3. NCA

    The code list says what those letters are

    news_allocate_to is the dictionary. The letters name the bucket. They do not calculate the percent. Two packages can both use CB / CS at different rates.

    AUCD The Australian, pay-as-you-go, bundle digital, weekend AUCW The Australian, pay-as-you-go, bundle print, weekend

    Characters 1–2 are the brand. AU is The Australian, which the finance sheet and the package code call TA. Characters 3–4 are the product. C is a pay-as-you-go bundle. D is the digital weekend side. W is the print weekend side.

    The percent is applied here. That program is not in the weekly script.
  4. NCA

    Cash is stored already split

    By the time a payment sits on news_financial_transaction, it has a product code, a gross amount, and a GST amount. One order line can carry several codes. For this package that is a line on AUCD and a line on AUCW.

    The eight weekly procedures do not read allocation_pct. The split has already become two cash amounts. Which program writes those amounts is the missing join.

    Each code is earned from its own cash
  5. Weekly job

    Once a week, earn each code on its own

    The offering decides the formula. No contract_offer means pay-as-you-go: positive ex-GST cash, spread evenly from the subscription start through the expire date, rounded. A contract earns each positive instalment from its due date. Either way the result is earned-to-date, then cut down if it exceeds net cash, then reduced by what earlier weeks already posted. That remainder is this week.

    AUCD and AUCW are earned separately. A refund on one code does not move the other. The print/digital percent is not revisited.

    The eight procedures are this station only. The order, the two chains, and a worked week are on the algorithm page.

    Sum every subscriber into one integer per code
  6. File

    The subscriber disappears

    The file has one row per product code for one earned date: the date, the 4-character code, and an integer. AUCD on this package is added to AUCD on every other package. There is no subscriber, no package, and no percent in the file.

    The sample file is Sunday 25 October 2026, written Monday 26 October 2026 at 06:00. The writer is not one of the eight procedures. The worklist cleanup, which drops a subscription once earned catches cash, does not change these integers.

    The code is mapped onto the account. That crosswalk is not in these sources.
  7. JDE

    JDE receives the code, not the package

    The 4-character code is mapped to a five-segment account: Entity, Publication, Department, Object account, Subsidiary. The first three are the business unit. Publication is where the masthead, and print versus digital, are distinguished. So AUCD and AUCW are expected to land on different publication segments: The Australian digital, and The Australian print.

    The table that turns AUCD into those five segments was not in the procedures, the allocation workbook, or the Think data model. The segments themselves are on the data-model page.

Three different clocks

Recipe date

The allocation’s effective date. This package’s is 1 July 2025. The extract does not keep the recipe it replaced, so an older week cannot be rebuilt from this file alone.

Cash date

When the payment was taken. The weekly job looks back to a long-standing start (the script’s commented value is 30 June 2014), not only to last week.

Earned date

The Sunday being closed. “Last week” is earned-to-date minus the amounts already stored on earlier earned dates.
